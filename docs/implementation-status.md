# 实现状态与已知限制

本项目发布的是已有工程成果和历史记录，不将策略目标包装成已验证能力。

| 原始目标 | 当前状态 |
|---|---|
| 仅 U 本位合约 | 筛选器使用 fapi；实盘客户端检查固定 base URL 和合约类型。未在发布时连接真实账户验收。 |
| 同时最多一仓 | 模拟服务一仓；公开配置将历史 `max_live_positions=3` 改为 1，但独立执行器、并发实例和手工交易并不构成全局锁。 |
| 15m/1h/4h 与 EMA20/50 | 实现主要采用 15m EMA9/21/55、1h EMA21/55 和微观资金流，不能视为原始三周期规则的等价实现。 |
| 净风险收益比至少 1.8 | 自适应退出存在较低 R 目标，没有完整双边手续费、滑点、价差、资金费和换仓摩擦的统一净 R:R 验收。 |
| 三档止盈 | 历史模块主要使用止损/止盈保护对，未实现完整的三档数量与成交后联动保证。 |
| 新仓保证金最多 50% | 存在名义仓位、余额缓冲及杠杆参数；不能将名义仓位百分比等同于可用保证金占用上限。 |
| 单轮一个主要动作 | 历史保护维护可能处理多个订单；当前没有覆盖所有写路径的统一动作预算。 |
| 每个实盘写操作需确认 | 入场有确认流程；`--confirm-live` 中的保护维护不是逐次人工确认。 |
| 保护始终存在 | 条件单取消/重建及入场/保护请求不是原子操作，网络和部分失败可能留下保护空窗。 |
| 超时下单不重复 | 请求重试路径未完成订单幂等性和不确定成交状态的系统性验证。 |
| 当前账户已验证 | 本次发布没有读取账户。档案中的账户结论只对应历史记录当时的可观测范围。 |

## 记录解释

- 早期运行仅查询普通 `openOrders`，其“无止损/无止盈”结论不能排除条件单，需要独立查询 algo orders。
- 早期扫描曾包括未收盘 K 线、简化 RSI/ATR 和有限候选范围，不能视为无前视偏差的回测。
- `-2015`、签名失败、超时或数据陈旧时，账户及持仓可能未知；安静的日志不代表低风险。
- `INSURANCE_CLEAR` 是需要复核的流水分类，不能仅凭名称断言每一条都是用户强平。
- 历史说明中的盈利、风险预算内、修复生效等结论没有在本次发布中通过原始私人数据重新验证。脱敏报告不用于收益统计。

## 公开快照的变动

替换私人凭据路径为项目本地 `.env`；环境变量在缺少该文件时仍可使用。测试中的真实网络地址替换为文档示例地址。默认扫描改为 40 个标的、6 并发和 60 秒间隔；实盘仓位配置改为 1、默认杠杆改为 1。

公开重启工具增加显式 `--enable-live-restart` 开关，并将进程及 screen 会话匹配限定到当前检出目录，避免接管另一份私有项目的服务。它仍是历史实盘工具，不在发布验证中启动。

公开示例使用本地日志，不强制连接 MongoDB。历史独立实盘工具仍有自身的强制审计检查；研究者启用实盘前必须自行设计和验证一致的审计、幂等、保护恢复、仓位锁、费用模型和熔断机制。发布验证只运行离线测试及命令帮助。
